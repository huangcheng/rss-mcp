# rss-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `rss-mcp`, a Python stdio MCP server (spec 2026-07-28) for agent-only RSS subscription management, fetch, list/read/search, and unread tracking backed by SQLite FTS5.

**Architecture:** Official `mcp` SDK v2 `MCPServer` over stdio exposes tools only. Domain logic lives in a SQLite store + HTTP feed client; tools are thin adapters. Protocol is stateless; durable state is the DB file.

**Tech Stack:** Python 3.11+, `uv`, `mcp>=2.3`, `httpx`, `feedparser`, `readability-lxml` (or equivalent), stdlib `sqlite3`, `pytest` + `pytest-asyncio`

**Spec:** `docs/superpowers/specs/2026-11-18-rss-mcp-design.md`

## Global Constraints

- Product/package name: `rss-mcp` (import package `rss_mcp`)
- MCP revision: [2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28) via official Python SDK v2
- Transport: stdio only; no GUI/TUI/CLI UX; tools-only (no Resources/Prompts/Apps)
- Storage: SQLite + FTS5; default path XDG `~/.local/share/rss-mcp/rss.db`; override `RSS_MCP_DB`
- Agent-sized defaults: list/search `limit` default `20`, max `100`; per-fetch new-entry cap default `50`
- User-Agent default: `rss-mcp/0.1 (+https://github.com/...)`; override `RSS_MCP_USER_AGENT`
- Commits: only when the human asks (plan steps may say “commit”; skip unless requested)

## Review Focus

- Malformed / non-feed HTTP bodies on fetch → tool result `isError`-style / structured error, DB unchanged for that feed’s entries
- Duplicate `add_subscription` same URL → idempotent return existing id, not a second row
- Entry without GUID → stable synthetic key from normalized URL (+ title fallback) so upserts do not duplicate
- `search_entries` with FTS special characters → sanitized/safe query, no SQLite error leaked as crash
- stdin closed / process shutdown mid-fetch → server exits cleanly; partial fetch does not corrupt schema
